# 本周踩的坑与整改 · 2026-11

> 记录来源：2026-11-02 ~ 11-07 的真实运行（M0–M5 编排 + M5 真实试点站 + 6 小时访客窗口）。
> 目的不是复盘谁对谁错，而是把**会再次发生的坑**写成能执行的规则。

---

## 0. 一句话结论

这一周产出了 12 次提交、约 28,600 行代码、22 个页面、零死链的站点，
但**真实访客 0、线索 0**。原因不是某一行代码写错，而是三件系统性的事：

1. 目标全在「产物侧」，验收标准里没有一条是「有人访问 / 有人留资」；
2. 「不编造 NAP + 不自动发帖」这两条规则叠加，**在设计上就让流量不可能发生**；
3. 部署与自检路径依赖一台**网络环境被劫持的机器**，而自检只看「进程还活着」，不看「公网打不打得开」。

## 1. 基础设施坑

### 1.1 端口 53 战争（最危险的一个）

- Clash Verge 开 TUN + `dns-hijack: any:53` + `dns.listen: :53` → 代理客户端自己占住 53。
- 我们的 `doh-dns.mjs` 也绑 `127.0.0.1:53` → **两个东西抢同一个端口**。
- 更糟的是 doh-dns 的上游 DoH 需要先解析域名 → 又被劫持 → **100% SERVFAIL**
  （日志里 `served=1068 failed=1068`）。
- 结果：谁抢到 53 谁说了算；抢到且答不出的一方会让「域名全废」，用户感知就是**断网**。

> **规则**：本包任何进程**不绑 53、不改网卡 DNS**。需要本地解析器就用 5354；
> 代理客户端的 DNS 端口也要让开 53。

### 1.2 隧道三连坑

| 方案 | 结果 |
|---|---|
| Cloudflare Pages（`wrangler deploy`） | OAuth 过期 → 部署从未成功 |
| 免费隧道 serveo / localhost.run | 能用，但**URL 每次都变**（share-link 里 14 个 URL），不能做长期入口 |
| Cloudflare 命名隧道 `mapsignal.hjh.pub` | DNS 记录建好了，服务却 `Stopped`；而且服务参数 `--dns-resolver-addrs 127.0.0.1:5354` **指向一个从来没有服务监听的端口** |

> **规则**：一个项目只能有**一条**对外路径，且必须有「进程在 + 公网通」双重证据。
> 端口参数上线前必须 `netstat -ano | findstr :5354` 验一次。

### 1.3 本机 DNS 不可信

- Clash 的 fake-IP（`198.18.0.0/16`）+ 企业通配符劫持，让 `nslookup` 看起来「正常」，
  但 `curl` 就是超时。
- 我们曾把这件事记成「公司 DNS 劫持」写进账本 decisions，**判断错了**——真凶是 Clash 的 fake-IP。

> **规则**：公网可达性**只能**用外部探针判定（microlink / allorigins / hackertarget DNS API）。
> 本机自检只能证明「本地进程活着」。判错了要在账本里更正，不能留着误导下一轮。

### 1.4 TUN 环路会让「一切看起来正常」的东西超时

- 代理节点服务器 `*.kunlun07dns.com` 全部解析到同一个 IP `18.167.19.80`，端口 14601–14634。
- Clash 的 TUN 默认路由（metric 0）会把**它自己出网的流量也吞进去** → 回环 → `i/o timeout`。
- 现象：TCP 握手「秒通」，5 秒后超时；纯 IP 访问 CN 站点却正常。

> **规则**：代理节点服务器必须**排除在 TUN 路由之外**（`route-exclude-address`）或用物理接口出网。

## 2. 编排坑

### 2.1 自我委派率 68%

68 次派单里 46 次派给 pi 自己。多模型编排退化成单模型串行，
`rules.json` 里的角色路由（design/frontend/seo→antigravity，review/social→grok）几乎没生效。

> **规则**：自我委派率 ≤ 40%；每个角色至少要有一个**不同厂商**的复核。

### 2.2 可追溯性：只有 16/68 次派单带 ticket_id

52 次派单在账本里查不到归属工单，失败也没法归因。

> **规则**：派单必须带 `ticket_id` + 一句验收语句，否则不记。

### 2.3 失败被静默吞掉

- 4 次 `exit=-1 closed by watchdog: the provider process is gone`——watchdog 直接杀进程而不是标记失败。
- grok 的失败主因是**未登录**（`grok login --device-code`），派单前没有预检。

> **规则**：provider 派单前做一次 1 秒级的**登录态预检**；watchdog 杀进程必须记为 `failed` 并带原因。

### 2.4 审批噪声淹没了真审批

55 张卡创建、23 张决策、7 张过期 → **25 张积压**，大量是
`\brm\s+-[a-z]*r` 全文匹配把 `grep "rm -r"` 误判成删除。

> **规则**：L3 规则必须**匹配命令位置**（首词为 `rm` / `Remove-Item`），
> 且 `grep` / 字符串里的 `rm` 不升级；`alwaysAsk` 只保留「对外发」。

## 3. 指标坑

### 3.1 「真实访客」口径把机器人算成了人

按项目自己的 `visitors.mjs` 口径，2337 条请求里有 **17 个「真实访客」**。
逐条看：Google（142.249/36.249）、DigitalOcean（microlink 无头浏览器）、
allOrigins —— **真人 0 条**，`leads.jsonl` 0 字节。

> **规则**：访客口径必须排除
> ① 探针 UA（node/curl/HealthCheck）、② 自机 IP、③ 已知探针基础设施（云厂商 IP 段 / allOrigins / referrer 含 checker 域名）。
> 数字宁可难看，不能自欺。

### 3.2 看门狗只看「任务还活着吗」，不看业务 KPI

`watchdog.json` 在 2026-11-06 06:39 报「进展正常｜没有待办」，
而那 6 小时的窗口目标正是「真实访客 ≥ 1」——**目标没达成，但看门狗是绿的**。

> **规则**：运行窗口必须带一个**可测的业务目标**（真人访客 ≥ N / 线索 ≥ N / 站点 200），
> 目标未达成时看门狗必须报红。

### 3.3 目标工单一直 `queued`

`tk-20261106-012111-GAWU`（修 3 个缺陷 + 恢复公网 + 6 小时破 0）从 11-06 01:21 起就没人派发。

> **规则**：窗口开始时，把**验收目标**和**缺陷工单**一起派出去；目标没派发 = 窗口没开始。

## 4. 决策层的结构性矛盾

| 规则 | 后果 |
|---|---|
| 不得编造 NAP | 站点无法创建 Google Business Profile → 这家「帮你上 Google Maps」的公司自己不在 Google Maps |
| 不自动发帖（无账号） | 社媒包 5 条草稿永远停在 `draft` |
| 一切对外动作要人点头 | 唯一的增长通道被完全锁死 |

→ 在这三条同时成立时，**流量为 0 是必然结果**，不是意外。

> **规则**：当验收目标（有人来）与安全约束（不许编造、不许代做身份验证）冲突时，
> 必须**显式升级给人**：要么补一次真 NAP + 一次人工身份验证，要么改目标。
> 不能让它在「都在做」的名义下耗掉一整周。
