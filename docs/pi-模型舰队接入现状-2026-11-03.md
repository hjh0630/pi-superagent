## 五、故障模式备忘（累计，别再踩）

1. **Windows 上 CLI 读 stdin 会挂死**：`codex exec` 提示 "Reading additional input from stdin..." 后无限等待 → 子进程 stdin 必须关闭（fleet 用 `stdio: ["ignore","pipe","pipe"]`）；但**登录类**命令相反，要用管道保活 stdin。
2. **后台进程未脱离 shell 会被回收**：`(cmd &)` / `nohup` 不可靠 → `powershell Start-Process`（或 `start /b`）；设备码流程必须保活 + 立刻给码。
3. **Git Bash 会改写 `/` 开头的参数** → 用 `MSYS_NO_PATHCONV=1`（`schtasks`、`pi-reach` 都踩过）。
4. **npm 全局 CLI 是 `.cmd` 垫片**：直接 spawn 会因引号崩 → fleet 解析到真实入口（gemini→`bundle/gemini.js`；claude→`bin/claude.exe`；agy→`D:\ai\Antigravity CLI\agy.exe`）。
5. **API 账号权益与网络是两件事**：codex 网络通了返回的是 400 权益错误，不是超时——分开排查。
6. **CLI 版本会被服务端强杀**：`grok` 0.2.112 报 426 要求 ≥1.0.13 → 任何 CLI 报 426/版本类错误，先 `xxx update`。
7. **VPN/TUN 模式下 curl 直连就通**，不必配 `HTTP_PROXY`；但本机 7890 端口在监听，排查时别把它当"代理没开"。
8. **钉钉待办列表**：一页最多 20 条、默认只返回执行人角色 → 必须 `--size 20 --role-types creator,executor,participant` 并翻页。
